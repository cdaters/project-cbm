## Content and distribution policy

Public candidates must include only software/content with reviewed redistribution
rights and required license/corresponding-source notices. Copyrighted software can
be lawfully distributed under its license; “no copyrighted software” is not a useful
policy for an image containing Linux, VICE and other licensed software.

The SHA-256-verified released v1.0.0 image contains VICE ROMs, demos, disk images and
magazine scans. Complete redistribution rights were not verified. A filename or a
“freeware” description is not permission. Private historical images, mixed bundles
and artwork may contain further unreviewed content and sensitive machine state.
Retain those originals privately; retention is not public-distribution approval.
The MIT grant for original CBM source/docs does not license every image asset.
See [evidence and limitations](provenance.md) and [security findings](security.md).
No released artifact was sanitized or replaced by these documentation corrections.

## Services

v1.0.0 contains an enabled TCPser unit despite its documented disabled intent.
An enabled unit does not prove a running listener or a working VICE IP232 connection.
SSH/Samba enabled-at-boot configuration is recorded, but Samba's helper and enabled
links disagree with the SMB-only configuration. Physical/service tests remain open.

For 1.1, [ADR-0001](adr/0001-base-distribution-and-image-architecture.md) selects an
explicit service policy as a build input: recommend TCPser opt-in and gate network
access on initialized identity and credentials. Exact SSH/Samba/Avahi defaults,
listener bindings and onboarding must be reviewed and tested during authorized
implementation. This document changes no service behavior.

## Credentials

Unix and Samba credentials must be treated separately. Changing the Unix password
through `passwd` or raspi-config is not evidence that Samba's password changed.
Samba's `unix password sync` controls the other direction: an SMB password change
may request a Unix password change. It is not proof of bidirectional synchronization.
[Upstream Samba configuration](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#UNIXPASSWORDSYNC)
and [smbpasswd](https://www.samba.org/samba/docs/current/man-html/smbpasswd.8.html)
describe these mechanisms (reviewed 2026-09-15).

Test both credential-change directions and client authentication separately,
including stale client credential caches. The audit did not test the advertised
passwords. New images must not inherit reusable credentials or host identity.

## Hardware and storage

Pi 3B/3A+/3B+, 4B/400, 5/500/500+ are intended targets where technically supportable.
Pi 3 is the performance floor; the 512 MiB 3A+ needs separate qualification. No
hardware cell passed physical testing in the audit. CM and Zero models are not
automatically included. [Hardware status](supported-hardware.md) is authoritative.
The historical 16 GB storage suggestion is not a measured minimum; no 8 GB minimum
has been mandated. Future footprint and usable free capacity require measurement.

## Checksums

The repository's [historical checksum copy](../checksums/v1.0.0/SHA256SUMS), added in
commit `37b5bff3d19b0c98ed0c8e306bfba036383c2439`, has a trailing bare digest without
a filename. It remains byte-for-byte preserved. Use the `SHA256SUMS` asset attached
to the [v1.0.0 release](https://github.com/cdaters/project-cbm/releases/tag/v1.0.0),
whose retained identity is 179 bytes, SHA-256
`bbd4fc904724c1a0249c340e39966c136906dc7d0f5c1f10a885c6eda3ac29f2`.
The image and docs hashes are also recorded in [provenance](provenance.md).
Do not assume a same-named repository file is byte-identical to the release asset.
A matching checksum is integrity evidence against a trusted reference, not a signature.
